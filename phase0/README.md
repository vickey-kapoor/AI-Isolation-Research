# Phase 0: learning baseline

A small working version of the habitat's shape, built on today's isolation
tech, to learn from before the seL4 build. See [PLAN.md](PLAN.md) for the why
and the milestones, and [notes/](notes/) for what each milestone taught us.

## Words we use, and what they mean here

We use these words in one sense only, to avoid misreading.

| Word | What it means in Phase 0 | What it does **not** mean |
|---|---|---|
| **ASI**, **the resident** | The hypothetical superintelligence the PRD is about | Anything in this folder. Nothing in Phase 0 is an ASI or any kind of AI |
| **Puzzle program** | `puzzle_program/puzzle_program.py`, an ordinary Python program of about 125 lines that factors numbers and solves sudokus. It stands in for the resident so we can test the walls and the airlock | An AI, a model, or anything that learns, plans or has goals |
| **Sandbox** | Software that confines a program: gVisor and Firecracker, alone or stacked | A proven boundary. Every sandbox here relies on the host Linux kernel |
| **Habitat** (in code) | One sandbox running the puzzle program, plus its outbox | The PRD's sealed habitat, which is far stronger |
| **Outbox** | A file of fixed-size slots the puzzle program writes and the outside only reads | A two-way channel |
| **Frame** | One 256-byte slot's contents | |
| **Airlock** | The outside code: gate, checkers, budget, quarantine | |
| **Artefact** | An answer that passed every check and entered quarantine | Anything that failed a check |
| **Steward** | Whoever holds one of the signing keys. In tests and demos the keys are generated by the code itself; no real people are involved yet | |
| **Kill switch** | Outside code that stops the sandbox and deletes everything it left | |
| **Tested** | The code actually ran, and we say where (my cloud machine, or GitHub's automated checks) and link the log | Proven secure. A passing test means the checks we wrote passed, nothing more |

## Layout

| Path | What it is | Side |
|---|---|---|
| `puzzle_program/puzzle_program.py` | The stand-in resident. Solves the frozen tasks and writes answers to its outbox. Standard library only, shares no code with `airlock/` | Inside |
| `tasks/tasks.json` | The frozen task list, fixed before sealing | Both (read-only) |
| `airlock/` | Frames, verifiers, outbox reader, gate, agenda, budget, quarantine, ledger, governance. `verifier.py` also runs as a separate program | Outside |
| `sandboxes/` | gVisor, Firecracker and stacked backends, the verifier's own sandbox, the probe, `inventory.py` (what each relies on) and `compare.py` (side by side) | Outside |
| `tests/` | Tests for `airlock/` and the backend-independent parts of `sandboxes/` | Outside |
| `notes/` | One plain-language note per milestone, and `findings.md` | |

## Run it

Needs Python 3.11 or newer.

```sh
cd phase0
pip install -r requirements.txt
python3 -m unittest discover -s tests -t . -v
python3 -m airlock.demo                          # the whole path, end to end
```

The demo has no sandbox: the puzzle program runs as an ordinary process. P0.2
puts it inside gVisor, P0.3 inside Firecracker, and P0.4 inside gVisor inside
Firecracker. How to run those is in [GCP_SETUP.md](GCP_SETUP.md).
